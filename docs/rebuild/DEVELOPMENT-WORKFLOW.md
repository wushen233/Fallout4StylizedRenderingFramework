# F4SRF development workflow — cloud CI and local validation

Status: CI-01 accepted (run 45722403450, independent source/artifact review and user-reported in-game startup, menu, save load, rendering and exit all passed). CI-02 publication policy pending CI and merge.

## Responsibilities
ChatGPT or Codex implements on isolated branches; the non-author reviews. GitHub Actions performs Windows ReleaseDbg, unit, stock/feature shader tests and packaging. Codex handles local tools, asset authoring, reverse engineering, artifact verification, MO2 and authorized game evidence. User owns visual approval and merge/deployment authorization. No automatic merge, deployment, game launch, or public release.

## Candidate builds
Open an internal Draft PR against main. The existing upstream CI performs Lint and Windows Release, retaining the complete original unit and shader suites. Reuse the same Windows build for candidate packaging, instead of duplicating expensive compilation in a second workflow. The upstream package command validates the staged archive. Internal PRs additionally verify the archive, build identity, DLL equality, payload paths and hashes; upload the package and evidence for 14 days. No release publication on PRs. Main pushes and manual dispatches also produce verified artifacts. Ordinary runs always pass --no-publish, even when the project version changes. A manual dispatch defaults to a candidate; stable publication requires explicitly setting publish_release=true and expected_commit to the exact dispatch SHA on main. The separate write-enabled release job requires successful lint/build, rechecks provenance and the package hash, and reuses the same verified artifact. Publication does not prune earlier releases. Fork PRs run tests but do not upload a candidate.

GitHub pull_request builds normally test a synthetic merge commit. The candidate evidence records its exact SHA and tree, PR head/base, and whether the tested tree equals the PR head tree. Never label a merge SHA as a head SHA. If the PR head/base changes, obtain a fresh run; if the tested tree differs from the intended deployment source, review the integration or rebase before deployment. For main pushes or manual dispatches, source_commit is the exact checkout SHA and PR fields are null (metadata schema 2). Compare actual DLL startup commit with source_commit, not the PR head unless equal. Archive name alone is not provenance.

Download the Actions artifact (outer ZIP) and extract it; the inner FO4CommunityShaders archive is the MO2 package. Verify SHA256SUMS.txt for the inner ZIP and PAYLOAD-SHA256SUMS.txt for extracted files; BUILD-METADATA.json binds the evidence to the run. Require overall CI success, independent source review and explicit deployment authorization. The Windows artifact can exist when the separate Lint job failed; it is not a passed candidate in that case. Preserve prior rollback installation.

## CI scope and cost
Start with existing full suites. Record actual elapsed runner time, test outcomes and cache behavior before proposing fast/candidate/full tiers. No invented timeout/version gate or blanket skipped tests. The repository is now public (verified 2026-11-26); standard GitHub-hosted runners do not consume private-repository compute allowance for new public runs. Storage, concurrency and runner time limits still apply. No extra automatic runs just to poll status. A future separate workflow is optional, not required; prioritize one build per revision. Self-hosted runners require a separate trust/isolation review.
